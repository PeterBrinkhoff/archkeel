# Known Delta action boundaries

Part of #542. The existing SemanticChange model owns exactly four actions understood by current Core production and governance: added, removed, relocated and changed. The public `SemanticChange.change: str` remains future-open wire data; every supported Delta version transports vendor actions unchanged. Current governance rejects unsupported actions at its own ingress with the original error.

`KnownSemanticChangeKind` is the one canonical domain used by the actual Delta classifiers, selected-change DTO, count policy, cycle checks and guardrails. Valid legacy ExpectedSemanticChange strings normalize once. Identity keys retain nominal actions; duplicate diagnostics explicitly retain plain wire tuple spellings. The narrower UnresolvedCallChange added/removed domain is unchanged. The obsolete, unpublished CHANGE_KINDS inventory has no remaining responsibility and is removed rather than retained through artificial usage.

The production cost is **85 additions / 43 deletions, net 42 lines in three existing files**, with no new production module or conversion framework. Four fingerprint scans become one typed grouping pass. Those buckets are created locally by `[]`; the qualified `_builtins.list.append` operation uses that concrete standard container port without restricting any external Mapping/list-like API or changing resolver authority.

The independently authored API Target pins the canonical enum, open wire field, actual producer parameter/return, selected-change field and governance ingress/count signatures. Native mutations reject field/return/parameter widening, public wire closure, and equality/membership/match/Final-alias dispatch regressions in actual migrated source projections. Whole mixed modules still have pending dimension/schema/cycle vocabularies: this increment does not claim complete Model/Delta/expectation string-dispatch absence.
