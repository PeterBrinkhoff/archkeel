# AD-227 Dependency rules use complete evidence for their own scope

A bounded source resolution gap must not invalidate unrelated `complete_requires`
evaluations. Keep the ordinary evaluator receipt, exact module selection, recursive
physical scan coverage and unique ownership checks. Separate receipt inventory roots
from the stronger dependency closure required by cycle rules.

Collectors may state the source-only resolution dimension `imports` or `signature`.
Core binds each gap's module, subjects and physical evidence to an observed library.
A signature exemption requires a native Dart constructor's unresolved super-formal
parameter and the same exact parameter evidence. Other signature gaps stay blocking.
Missing, legacy, contradictory or unmappable attribution proves no local completeness;
diagnostic wording never determines eligibility. Parts are physical selected inputs,
not additional library modules; an unproved part attribution remains blocking.

Core certifies only requires receipts unaffected by unresolved imports after complete
selected-input reads/parses, valid runtime, applicable supported rules and authenticated
contract loading. Bind the proof to source and contract digests, the validated runtime,
selected files, module/import inventories and all coverage gaps. Bind the exact source,
evidence and permission records too. Failed Target authentication and late runtime
diagnostics revoke it. A later projection rechecks these bindings and unique scope
ownership; an ordinary old receipt cannot bypass incomplete observation.
Saved scoped proofs support only the native Python runtime's dotted numeric lower
bound; unsupported requirements fail closed instead of using a general version parser.

Unresolved Flutter superclass parameters still retain unknown types/defaults and
incomplete signatures. Arbitrary TypeScript `import(id)` stays unresolved, blocking
its owning scope and affected ancestors. Global coverage remains FAIL, exit code 2,
and missing UML evidence stays UNKNOWN. Observed, traceable violations remain FAIL.

Reject global coverage relaxation, invented dynamic-import targets, copied Targets,
diagnostic allowlists and renderer inference. Saved reports, rule explanations and
module cells use the same scoped receipts without reevaluation.

Command-result 8 reads unchanged version 6/7 packets and adds incomplete report FAIL
with a required FAIL assessment, or an explicit rule/component lens which may omit
that assessment while retaining the global verdict. Keep published 6/7 unchanged: their
unfiltered exit-2 contract previously required UNKNOWN. Other commands and incomplete
PASS remain rejected. SourceFacts and ArchitectureIR versions do not change.
