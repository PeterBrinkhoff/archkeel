# AD-220: Exact alias body permissions

For [issue #438](https://github.com/rapiddweller/archkeel/issues/438), contract
3.0 permits an exact boundary selector to bind the proven direct alias's
`origin` and complete canonical `shape`. Both are nonempty strings; names
are data. The supported nongeneric two-slot tuple family is described in
[rules](../../rules.md). Chains, wrappers and ambiguous source bindings fail
closed. Its unique map is at depth 2; a separate depth-3 selector accepts
THREE syntactic native leaves. Metadata findings and UNKNOWNs remain independent.
Proven standard `TypedDict` metadata with literal `total=True` or `total=False`
also qualifies; dynamic or ambiguous headers fail closed. Header identity
does not establish field closure.

Reuse immutable type shapes, existing codecs and selector coordinates.
Target displays declarations; Actual displays applied facts; Diff separates
both. Only a unique exact valid pair can lend rationale. Malformed saved data
stays in the audit without a fabricated join. Accepted opacity proves no closure.
Applied facts distinguish observed container depth from the selected depth;
the map selector keeps its depth absent.

Register `origin` in the existing module-reference inventory with `held=False`.
Proven renames translate it for historical comparison; they never rewrite the
opaque byte-exact `shape`. Changing an embedded metadata origin requires an
explicit binding amendment.

This extension requires package 2.0 and opt-in contract 3.0. Legacy contract
vocabulary, defaults and absent-binding bytes stay unchanged. The collector adds
optional source-only `typed_dict_header_static` proof; existing header/native-owner
flags and member inventories stay unchanged. Proven records and collector
`code_digest` change; SourceFacts, observation and command envelopes keep their
versions. CE contracts stay untouched.
